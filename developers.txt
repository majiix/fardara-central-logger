1. OVERVIEW & INTEGRATION PHILOSOPHY
--------------------------------------------------------------------------------

Fardara Central Logger (`fardara-central-logger`) is a standalone WordPress
logging engine designed to consolidate logs across a multi-plugin ecosystem.

Integration Principles:
1. Zero Runtime Dependencies: Central Logger does not require Composer packages
   in client plugins.
2. Defensive Integration: Client plugins must never crash or throw errors if
   CentralLogger is disabled, uninstalled, or loading later in the execution
   sequence.
3. Two-Dimensional Scoping: Every log event has a Severity Level and an Event
   Category. Both can be configured globally or overridden per-plugin.
4. Automatic Context Enrichment: Client IP addresses and current user IDs are
   automatically captured if omitted by the calling plugin.
5. Privacy by Default: Sensitive context data (passwords, tokens, emails, IPs,
   credit cards) is automatically scrubbed before database persistence.

2. PUBLIC API SPECIFICATION
--------------------------------------------------------------------------------

Central Logger provides two public API interfaces:
- Procedural API (Global Functions)
- Object-Oriented API (PSR-3 Style Class)

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
2.1 Procedural API
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Function: central_logger_log()
------------------------------
Logs an event to the centralized database.

Signature:
function central_logger_log(
    string $source_plugin,
    string $level,
    string $message,
    array $context = [],
    string $category = 'system'
): bool

Parameters:
- $source_plugin (string, required): Unique slug of the calling plugin
  (e.g., 'fardara-checkout', 'fardara-inventory').
- $level (string, required): Severity level ('debug', 'info', 'warning',
  'error', 'critical').
- $message (string, required): Descriptive log message.
- $context (array, optional): Associative array of structured data.
- $category (string, optional): Event category (default: 'system').

Return Value:
- (bool): True if the log was accepted and saved; false if rejected by active
  thresholds, disabled categories, rate limits, or database failure.

Example:
if (function_exists('central_logger_log')) {
    central_logger_log(
        'fardara-checkout',
        'error',
        'Payment gateway returned a failure code',
        [
            'gateway'     => 'stripe',
            'order_id'    => 10842,
            'error_code'  => 'card_declined',
            'charge_time' => 1.42,
        ],
        'integration'
    );
}

Function: central_logger_should_log()
-----------------------------------
Pre-checks whether a log entry would be recorded given active settings.

Signature:
function central_logger_should_log(
    string $source_plugin,
    string $level,
    string $category = 'system'
): bool

Parameters:
- $source_plugin (string, required): Plugin slug.
- $level (string, required): Severity level.
- $category (string, optional): Event category (default: 'system').

Return Value:
- (bool): True if an entry with this level and category would be accepted.

Example:
if (function_existsS('central_logger_should_log') && central_logger_should_log('fardara-reports', 'debug', 'performance')) {
    $context = [
        'query_count' => get_num_queries(),
        'memory_peak' => memory_get_peak_usage(true),
        'backtrace'   => wp_debug_backtrace_summary(),
    ];
    central_logger_log('fardara-reports', 'debug', 'Report generation profile', $context, 'performance');
}

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
2.2 Object-Oriented API (\CentralLogger\Logger)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Class: \CentralLogger\Logger
----------------------------
A scoped instance pre-bound to a specific plugin slug and default category.

Constructor:
public function __construct(
    string $sourcePlugin,
    string $defaultCategory = 'system'
)

Instance Methods:
- shouldLog(string $level, ?string $category = null): bool
- debug(string $message, array $context = [], ?string $category = null): bool
- info(string $message, array $context = [], ?string $category = null): bool
- warning(string $message, array $context = [], ?string $category = null): bool
- error(string $message, array $context = [], ?string $category = null): bool
- critical(string $message, array $context = [], ?string $category = null): bool
- log(string $level, string $message, array $context = [], ?string $category = null): bool

Example:
if (class_exists('\CentralLogger\Logger')) {
    $logger = new \CentralLogger\Logger('fardara-auth', 'auth');

    // Uses default category 'auth'
    $logger->info('User authentication succeeded', ['user_id' => 45]);
    $logger->warning('Failed login attempt detected', ['username' => 'admin']);

    // Overrides category on specific call
    $logger->critical('Potential brute force attack blocked', ['ip' => '203.0.113.19'], 'security');
}

3. SEVERITY LEVELS & EVENT CATEGORIES REFERENCE
--------------------------------------------------------------------------------

~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
3.1 Severity Levels (Ascending Hierarchy)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

1. 'debug' (Weight: 100)
   Verbose diagnostic data, internal step-by-step execution traces, SQL query
   timings, algorithm state snapshots.
2. 'info' (Weight: 200)
   Normal operational events and milestones (e.g. order completed, batch job
   finished, email queued).
3. 'warning' (Weight: 300)
   Non-fatal anomalies, deprecation warnings, retry attempts, recoverable API
   errors.
4. 'error' (Weight: 400)
   Runtime errors, failed operations, database write errors, unhandled
   exceptions that stopped a single transaction.
5. 'critical' (Weight: 500)
   Critical failures requiring immediate attention (e.g. database down, payment
   gateway offline, security breach attempt).

Threshold Matching Rule:
A log entry is accepted if:
  LogLevel::getWeight($entryLevel) >= LogLevel::getWeight($activeThreshold)
